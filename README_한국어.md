# 도깨비의 세계 런처 — healthy 이후 충돌 복구 후보

**상태:** GitHub 미반영 · Windows 실사용 미검증 · 사용자 원본 미변경. 기존 공개 `launcher-v0.0.3` Release는 유지된다.

## 구현 범위

- 기존 시작 전 오류(`pending`) 복구는 다음 호스트 실행 시 기존처럼 처리.
- 시작이 정상 확인된(`healthy`) 뒤 런처 프로세스가 **비정상 종료(0이 아닌 종료 코드)**되면 설치된 이전 버전을 활성화. 즉시 자동 재실행하지 않으며 사용자가 다음 번에 열면 이전 버전 실행.
- 정상 종료(종료 코드 0)는 복구하지 않음.
- 실행 세션 ID 및 현재 버전 대조로 다른 런처 창이나 새 업데이트에 의한 덮어쓰기 방지.
- 기록기 버전, 기록, 설정, 사용자 배경과 UI 디자인 변경 없음.
- 기존 VBS 실행은 계속 숨김 처리. 개발용 BAT 직접 실행은 앱이 종료될 때까지 콘솔이 남을 수 있음.
- 하드웨어 전원 차단·프로세스 종료코드가 0으로 반환되는 비정상 상태·Windows 보안 소프트웨어의 프로세스 중단 모두를 복구한다고 보장하지 않음.

## 검증

로컬 Python 단위 시험 15개 통과. 적용/롤백 시 임시 사용자 데이터 파일 바이트 보존, 알 수 없는 호스트·다른 설치 백업·진행 중 업데이트 거부 확인. GitHub Windows CI 및 실제 사용자 PC의 실행은 **아직 미검증**.

## 원본에 직접 설치하기 전에

**권장:** 먼저 Codex에게 `git.patch`를 신규 브랜치에 적용하고 GitHub Windows CI + 격리된 GUI 재시작 시험을 수행하도록 지시. 검증 완료 전에는 사용자 실사용 폴더를 변경하지 말 것.

사용자가 별도로 실사용 적용을 선택하는 경우, 런처와 기록기를 모두 종료하고 설치 폴더 전체 백업을 먼저 한 뒤, 압축을 **설치 폴더 바깥**에 풀어 PowerShell에서 다음 명령 사용:

```powershell
py -3.12 tools\host_recovery_upgrade.py inspect --root "실제 설치 폴더"
py -3.12 tools\host_recovery_upgrade.py apply --root "실제 설치 폴더" --backup "설치 폴더 바깥의 존재하지 않는 새 백업 폴더" --apps-closed
```

적용 후 런처 정상 실행 여부를 확인. 문제가 생기면 런처·기록기 모두 종료 후:

```powershell
py -3.12 tools\host_recovery_upgrade.py rollback --root "실제 설치 폴더" --backup "위에서 만든 백업 폴더" --apps-closed
```

도구는 현재 설치된 호스트 SHA가 기존 `v0.0.3` 검증 SHA와 정확히 일치하지 않으면 자동 적용하지 않음. 사용자 데이터 폴더나 자동 업데이트 버전을 건드리지 않음. 정상 종료 신호 없이 강제 종료했을 때만 원복 대상.

## Codex에 통합할 때

1. main `8a5151f67f6058e72696d4e2c38658b0b75f7a02`에서 새 브랜치 생성.
2. 리포지토리 루트에서 `git apply --check git.patch` 후 `git apply git.patch` 실행.
3. Python 3.12 / Windows에서 `python -m unittest discover -s tests -v` 수행. 격리된 실제 런처 UI에서 healthy 이후 강제 비정상 종료 및 정상 종료, 이전 버전 복구, BAT/VBS 실행을 점검.
4. UI·배경 원본 무변경 / 기록·설정 해시 보존 확인 후 PR 작성.
5. 안전한 승인·배포 절차를 준수하고 `launcher-v0.0.3` Release를 덮어쓰지 않음. 필요 시 차기 버전과 별도 host 전환 패키지를 설계.

이 패키지는 테스트 및 통합 준비물이며 **정식 배포 파일로 가장하면 안 됨**.
